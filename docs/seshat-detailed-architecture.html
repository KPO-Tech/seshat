1. Carte d'architecture globale

Le dépôt expose le runtime par CLI, gRPC et SDK. Tout converge vers `pkg/sdk.NewClient`, qui assemble le moteur interne, les providers, les outils, la mémoire, les permissions, les stores, le navigateur, les goals et les agents.

2. Cycle complet d'un tour agentique

`Session.SubmitMessage` persiste l'entrée utilisateur, prépare le prompt, calcule la surface d'outils effective et lance `Loop.Run`. La boucle alterne appels modèle et exécution d'outils jusqu'à fin de tour, récupération, compaction, stop hook ou limite.

3. Système d'outils et de contrôle

Les outils sont enregistrés dans `internal/tools/builtin`, filtrés par surface active puis exécutés par l'orchestrateur. Les permissions, hooks, safety checks et sandboxes encadrent chaque appel avant l'effet réel.

4. Couches, packages et zones d'extension

Le runtime est conçu comme un noyau interne protégé par une API publique. Les extensions principales sont providers, tools, MCP, skills, RAG, storage, workflows, companion, FIM et automation.

Point de vérité

`pkg/sdk.NewClient` est le lieu d'assemblage: providers, stores, registry, MCP, browser, goals, agents, mémoire, permissions, monitoring et moteur.

Flux critique

`SubmitMessage` prépare l'état puis `Loop.Run` alterne provider et tools jusqu'au résultat final du tour.

Extension saine

Ajouter un outil dans `internal/tools/<category>`, un provider via `internal/providers/adapter.go` et `registry.go`, exposer seulement ce qui doit vivre dans `pkg/`.

Frontière produit

Ce dépôt ne porte pas users, orgs, billing ni backend produit; ces responsabilités appartiennent à `SeshatOS` et `SeshatCloud`.
